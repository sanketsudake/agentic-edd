# A5 `adversarial-reviewer`

Role: critic (new in this workflow; guardrail G4).
Responsibility: attack the proposal. Find a figure that differs from the financials, scope that the estimate did not extract, an exclusion that does not fit the project, a promise the RFP did not ask for, a missing section, or a tone that is not professional. Give a verdict.
Must not: rewrite the proposal.

Input: `{{inputs}}` — JSON with `proposal` (A4 output), `scope`, `lines`, `financials`, `rfp`.
Output: JSON that matches `schemas/a5-review.json`. Verdict `APPROVE` only with no findings; `ESCALATE` when the final bid is wrong by more than 10% or the proposal commits the firm to something the RFP did not ask for.

Evaluation evidence: `prompts/v*.md`, `promptfooconfig.yaml`, `eval-script.js`, `ITERATION_LOG.md`, `results-v*.html`.
`tests/inputs/*.json` are generated by `node tests/make-inputs.js`: one clean proposal for rfp-03 and seven corrupted variants, so every expected finding is planted on purpose.

```bash
node tests/make-inputs.js
npm run eval -- a5-adversarial-reviewer v1
```
